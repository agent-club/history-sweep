## Release notes

Browse pages by visits within a selected period, keep a preferred view and relative range, and start with websites from the past week. Use Private cleanup to avoid saving new cleanup activity. Navigate long lists with Back to top, adjust Chrome's current shortcut, or keep your preferred popup/modal/workspace opening method. Manually transfer lightweight settings through your own WebDAV file and export an encrypted disk backup for recovery after uninstall. Store updates use Chrome's official download and install flow.

Frequency ranks period visits, while date and website views filter each URL's last visit. Deletion removes all visits to selected URLs, including visits outside the range, and cannot be undone. Chrome may propagate deletion to other signed-in devices.

## Privacy fields

Single purpose: Help users find, review, select and delete Chrome browsing history, with local browsing preferences and user-initiated backup of lightweight extension configuration.

- `history`: Read matching URLs, titles, last-visit times and visit details locally; calculate period counts; delete only confirmed selected URLs; verify remaining visits. History is never uploaded.
- `activeTab`: Read the current URL for a user-invoked website search or insert the selected modal, without collecting page content.
- `scripting`: Insert the bundled modal host after user invocation; no remote script is executed.
- `contextMenus`: Add the user-invoked current-website search entry, without automatic selection or deletion.
- `storage`: Save kept-domain rules, opening/browsing defaults, Private cleanup preference, local activity summaries, update-check cooldown, WebDAV connection settings and reserved configuration metadata on this device. Complete deleted URLs are not retained.
- `favicon`: Display Chrome-provided website icons in grouped results and local activity.
- Optional HTTPS host access: The WebDAV adapter requests only the selected hostname when the user tests or transfers. It performs GET and conditional PUT against the saved HTTPS file URL. Saving settings or exporting a disk backup makes no server request. Host permissions cover ports on the selected hostname; the transfer still uses the exact saved URL and port.

Remote code: None. Scripts, styles, translations and icons ship inside the ZIP. HTTPS responses are JSON configuration or public version metadata; they are validated as data and never executed.

Data practices: History and search remain local. Manual WebDAV JSON includes language, appearance, opening preference and reserved label configuration structures; it excludes history, cleanup activity, kept-domain rules, browsing defaults, Private cleanup preference and credentials. Server authentication uses user-entered credentials over HTTPS; the selected provider receives those credentials for authentication and can read remote JSON. Cookies, referrers and redirects are disabled. The developer does not receive these configuration transfers. Local connection storage is not a password vault.

Encrypted backups contain connection credentials and lightweight configuration, use a user-entered password that is not stored, and are manually saved/imported. Uninstall removes extension storage; recovery requires the backup file and password. No automatic post-uninstall retention is promised.

The official store installation requests public JSON version metadata at most once per 15 minutes when opened. No history, query or configuration accompanies that request; the website host receives standard connection information. Unpacked/forked/managed installations skip it. Only Chrome-confirmed downloads enable Update; active deletion/verification prevents reload. A signed store-upgrade test remains separate from synthetic update-response checks.

The public privacy URL must describe these practices before submission. Preserve accurate Limited Use declarations and distinguish access to history from transmission of history. Do not infer permission/privacy checkboxes solely from the phrase "no history upload."

## Reviewer walkthrough

Use a disposable profile and synthetic history, with no real credentials required for local browsing or encrypted backup.

1. Open with no saved preferences: By website and the past week appear. Switch among date, website and frequency, retaining the query/range. Frequency counts visits in the selected period, including pages visited again afterward.
2. Save default view/range in Preferences, confirm the current view stays unchanged, and reopen. Custom dates are temporary. Keyword searches default to all time until dates are explicit.
3. Select test URLs, cancel once, then confirm. Verify all visits to selected URLs are removed and unselected URLs remain. Closing the view does not stop a confirmed task; keep Chrome running.
4. Save Private cleanup, delete a test URL and verify no new activity totals/details are recorded. Existing activity remains. Check Back to top and the current shortcut settings entry.
5. Open Sync & disk backup. With no connection, export/import an encrypted settings backup and check the confirmation preview; an incorrect password must not apply data. Uninstall recovery requires that file and password.
6. To test WebDAV, use the reviewer's own controlled HTTPS WebDAV file with an existing parent folder and conditional-write support. Approve host access only for that server. Test/upload/download are manual; download previews before applying. Declining access must not contact the server. No shared test credentials are embedded in this package.
7. Unpacked review installs skip website version checks. Chrome Store upgrade behavior requires a signed store installation; local tests use synthetic store responses and do not prove public rollout.

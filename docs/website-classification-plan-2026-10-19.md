# 网站自动分类规划

周期：2026 年 10 月 19–25 日，主要工作日为 19–23 日。状态：完成首轮资料调研与方案整理，待对稿和服务原型验证。

目标是自动识别网站属性，在 History Sweep 中展示可修改的分类标签。先验证公开网页 TDK 抽取与公开分类数据，可靠时归类，无法判断时不展示标签。分类展示、用户修改和展示控制组成同一功能；不改变历史记录的选择、保留和删除规则。

## 已确认需求

- 自动分类至少覆盖社交、博客、周刊、色情相关内容；Medium、CSDN 按用户要求作为博客类验收案例。
- 服务自动抓取公开网页，抽取 Title、Description、Keywords 等信息并分类；不依赖用户逐站维护规则。
- 调研备案及其他公开信息对色情分类的帮助。
- 无法可靠分类时不处理，不强行填入“其他”。
- 用户可以修改自动标签及其展示；偏好设置提供分类展示控制。
- 用 ImageGen 出概念稿，覆盖分类展示、分类编辑、展示控制三个场景。功能实现属于后续迭代。

## 首轮调研结论

| 信号或数据源 | 能提供什么 | 使用边界与方案 |
| --- | --- | --- |
| Chrome History API | URL、标题、访问时间和次数等历史字段，没有网页 Description、Keywords | 历史接口不足以完成 TDK 抽取；需要独立公开网页抓取服务。[官方字段](https://developer.chrome.com/docs/extensions/reference/api/history#type-HistoryItem) |
| 网页 TDK | 网站自述的标题、描述及关键词 | 作为候选信号，允许字段缺失或矛盾；不能仅凭一个词下结论。Google 文档确认不使用 keywords 标签参与搜索排名，这不等于它对本分类器无价值，权重仍需实测。[元信息说明](https://developers.google.com/search/docs/crawling-indexing/special-tags) |
| Cloudflare Domain Intelligence | API 返回域名内容分类；分类表区分 Adult Themes、Nudity、Pornography | 可做公开域名类别候选源。宽泛的 Adult Themes 不直接等同色情，只有明确匹配且通过样本验证的类别才映射色情。接口需要服务端凭据，普通 Free、Pro、Business 当前均为每月 100 次，不能假设可免费覆盖全部网站。[接口](https://developers.cloudflare.com/security-center/intel-apis/)、[类别定义](https://developers.cloudflare.com/cloudflare-one/traffic-controls/domain-categories/)、[额度](https://developers.cloudflare.com/security-center/intel-apis/limits/) |
| UT1 公开分类库 | 提供 adult、blog、social_networks、sexual_education、mixed_adult 等列表，维护者说明重点维护 adult | 可评估服务端定期导入，避免逐站请求第三方；列表存在误分。adult 范围从情色到色情，mixed_adult 不能直接赋给整个综合平台；性教育单独排除。维护页链接 CC BY-SA 4.0，接入时需落实署名及适用的衍生数据义务。[维护方说明](https://dsi.ut-capitole.fr/blacklists/index_en.php)、[许可](https://creativecommons.org/licenses/by-sa/4.0/) |
| 工信部公开备案查询 | 查询网站名称、备案号、首页地址和域名 | 所查官方页面没有色情内容标签，并有验证码和查询限制。方案只把备案用于站点身份辅助；不能用未备案、境外注册或查不到记录推断色情，也不依赖绕过验证码实现自动化。[查询字段](https://app.gjzwfw.gov.cn/jmopen/webapp/html5/fjyxhlwxxfwbacx/index.html) |

以上核验了公开文档与当前扩展配置，尚未进行带凭据的 API 调用、分类库全量下载、网页抓取实验或分类准确率测评。服务是否满足覆盖率、成本和时延要求，留到原型验证。

当前 `extension/manifest.json` 使用 `connect-src 'none'`，未声明抓取任意网站的 host permissions；项目 README 承诺浏览记录留在本机。接入在线分类将引入域名传输，必须明确更新用户告知、按需启用方式、联网权限及对应隐私说明。本轮仅规划，不变更上述配置和承诺。

## 建议分类口径

分类体系先采用少量固定类别，社交、博客、周刊为网站形态；色情为独立的内容属性，两者可以同时存在。资讯、工具为概念稿中的候选扩展类别，首期是否纳入需对稿定稿。

| 类别 | 正向依据 | 容易误分的情况 |
| --- | --- | --- |
| 社交 | 用户关系、互动发布是站点主要用途 | 有评论区不代表整个网站是社交站 |
| 博客 | 作者文章、博客平台、个人文章归档是主要形态 | Medium、CSDN 作为博客案例；单篇新闻稿不代表博客 |
| 周刊 | 有连续期号、周期性精选或明确周刊描述 | 域名或标题含 weekly 不足以证明；综合平台上的一份周刊不能让整个域名变成周刊 |
| 色情 | 明确色情类别命中及经验证的公开内容证据 | 新闻报道、医学、性教育、艺术裸露、交友及混合内容平台不因关键词或宽泛成人标签被整体标记 |

首版建议按精确 hostname 存储和展示，不能用最后两段字符串猜主域。子域、托管博客和综合平台均不能自动互相继承分类。路径级周刊、栏目与独立作者空间先保留未分类；后续确需页面级分类时，再评估路径传输及单独授权。分类未命中只是不展示标签，不代表网站安全或不存在色情内容。

概念稿暂使用“成人内容”作为中性展示名，内部保留色情、裸露、性教育等原始类别区别；该文案与是否默认展示需对稿确认，不能以文案合并扩大判定范围。

## 自动服务方案

建议采用“公开域名抓取服务 + 分类任务队列 + 共享分类缓存 + 扩展本地覆盖”，首轮先验证抓取与分类，再决定是否接入扩展。

1. **限定输入。** 后续用户启用在线分类后，仅提交允许分类的公开 hostname，去掉路径、查询参数、片段、访问时间和次数。IP、localhost、内网和配置排除项不提交；自定义内部域名的排除策略也须验证，公网 DNS 可解析不自动等于公开网站。
2. **缓存查询。** 按 hostname、分类体系版本、来源版本命中已验证且未过期的分类。排队与失败均不阻塞历史列表，抓取请求合并去重，限定并发和单域频率。
3. **抓取公开入口。** 先请求 HTTPS 首页，提取 HTML 的 TDK。数据不足时，可在预算内读取同站公开 About、RSS/Atom 或 JSON-LD 的站点形态信号；各字段独立保留缺失状态，不伪造 Description 或 Keywords。
4. **有限渲染。** 对需要 JS 的站点才尝试隔离的无头浏览器；不携带用户 Cookie、不登录、不绕过验证码。登录墙、不可达、robots 限制、反爬与超时均可返回无法分类。
5. **生成候选。** 公开分类库提供已知域名标签，规则和文本分类模型判断社交、博客、周刊。若引入大模型，只向其提供已清洗、截断的公开内容和固定类别定义；模型、供应商与预算通过验证后再选型，不先承诺特定服务。
6. **证据裁决。** 来源冲突、证据不足或模型输出不合法均返回空结果。色情标签使用更严格、经标注样本校验的发布门槛；单个模型自报高置信度不等于可发布。校准前不指定貌似精确的分数阈值。
7. **异步更新。** 扩展读取结果后刷新自动标签；用户覆盖保留在本机，不回传为全局训练标签。缓存到期重新验证，失败保持无可用自动分类；不会把旧的色情标签当作新鲜判断。

抓取服务必须在每次 DNS 解析及跳转时阻断内网、回环、链路本地和云元数据地址，防止通过重定向或 DNS 变化访问内部资源；限制响应体、跳转次数、耗时和浏览器资源。网页文字视为不可信数据，不能让其中的指令调用工具、改变类别规则或上传内容。

服务端只保留分类需要的公开站点证据、来源、版本及更新时间；请求日志不记录完整网址或可关联个人的浏览序列。域名仍可能透露浏览兴趣，因此“仅域名”不能表述为“完全没有数据传输”。首轮只用明确选择的公开案例、保留域和供应商测试夹具，不读取或上传真实浏览历史。

待比较路线：先评估服务端导入 UT1 等公开分类库与自有 TDK 分类，Cloudflare API 用于小样本交叉验证；是否采购额外额度，由覆盖、误分率与成本结果决定。不直接把第三方的大类当作本产品标签。

## 用户编辑与展示设置

以下为建议行为，概念稿用于对稿：

- 自动结果和用户覆盖分开保存。建议自动记录包含 hostname、类别、来源、证据摘要、版本、更新时间、过期时间及处理状态；本地覆盖区分“跟随自动”“替换为用户标签”“不显示此网站分类”，防止清空标签后又自动出现。
- 用户可选预设分类、修改为本地自定义标签或移除当前标签。编辑范围是当前精确 hostname；不重命名全局系统类别、不影响其他用户。
- “恢复自动分类”移除当前本地覆盖；此时若没有有效自动结果，就不显示标签。自动更新不得覆盖手动修改，取消不保存。
- 建议展示计算顺序为：全局展示开关 → 网站级隐藏/替换 → 有效自动结果 → 分类可见性过滤。无结果保留空白，不补“其他”或“未知”。
- 偏好设置分开提供“显示网站分类”“显示的分类”和“自动分类服务”。展示开关只影响标签，不改变网络服务开关，也不隐藏网站记录。
- 在线服务建议默认关闭；用户了解域名用途并主动启用后才发起查询。色情相关标签建议默认不展示，其余标签默认展示，最终默认值需对稿确认。
- 设置提供“管理已修改的分类”入口；系统标签及本地自定义标签均可控制展示。关闭在线服务停止新请求；已有有效缓存与用户标签是否显示由展示设置决定。

### 验收清单

- [ ] Medium、CSDN 的博客标签符合约定；社交与周刊有正例及易混反例，不能只靠域名或关键词命中。
- [ ] 缺字段、不可达、来源冲突及无法判断均不展示虚假标签；分类服务失败仍能查看和删除历史。
- [ ] 裸露、性教育和含少量成人内容的综合平台不会因上级类别被整体判作色情；不使用备案缺失推断内容。
- [ ] 已提交的用户标签和网站级隐藏在刷新、重开及自动分类更新后保持；取消、恢复自动符合定义。
- [ ] 总开关、类别开关和服务开关独立生效；隐藏分类不隐藏记录，不触发选择或删除。
- [ ] 域名提交、内网排除、重定向校验、缓存过期及抓取资源限制有可复现验证。
- [ ] 服务未启用时无分类联网请求；启用时不发送完整 URL、访问序列、Cookie 或本地用户标签。
- [ ] 数据许可、服务配额、分类质量、成本和用户告知满足接入条件后，才进入生产接入。
